# LucidCue Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build LucidCue, a sideloaded Connect IQ watch app for the Garmin Epix Pro (Gen 2). It estimates REM sleep from motion and heart rate, delivers a trained vibration cue to induce lucid dreams, and logs nights for calibration.

**Architecture:** The night-time logic is four hardware-free units: epoch features → sleep state machine → REM detector → cue controller. Each is written twice. First comes a Python reference model with pytest, runnable anywhere and reused by the calibration script. Then comes a Monkey C port, checked against fixtures generated from the Python model. Thin Monkey C wrappers handle sensors, vibration and logging, and four screens provide Train / Night / Morning / Summary.

**Tech Stack:** Monkey C + Connect IQ SDK (watch app), Python 3.11+ with pytest and matplotlib (reference model, calibration, fixture generation).

**Spec:** `docs/superpowers/specs/2026-10-09-lucidcue-garmin-design.md`

## Global Constraints

- Target devices: Epix Pro (Gen 2) product IDs `epix2pro42mm`, `epix2pro47mm`, `epix2pro51mm`. Verify the IDs in SDK Manager's device list and fix `manifest.xml` if they differ. App type `watch-app`, `minApiLevel="3.2.0"`, permission `Sensor` only.
- Epoch length 30 s. Timestamps are Unix seconds (`Time.now().value()` / Python `int`).
- Accelerometer units milli-g. Accelerometer sampled at 10 Hz via `Sensor.registerSensorDataListener` with `:period => 1`.
- Monkey C REM/cue arithmetic on HR and variability uses `Double`, not `Float`, so results match the Python model exactly. Write Double literals with the `d` suffix (`1.05d`) and convert settings via `.toDouble()`.
- Defaults (both languages): `noiseFloorMg=30`, `stillThreshold=500`, `wakeMotionThreshold=5000`, `hrRise=0.05`, `varRatio=1.3`, `earliestCueHours=4.5`, `maxCuesPerNight=6`, `startLevel=30`, `levelStep=15`, `levelMax=80`, `levelMin=10`, `trainReps=5`, `calibrationMode=true`, `vibeByLength=false`.
- Setting ranges (clamp on load): `earliestCueHours` 2.0–7.0, `maxCuesPerNight` 1–10, `startLevel` 10–80, `trainReps` 3–10, `hrRise` 0.00–0.20, `varRatio` 1.0–2.0.
- Fixed constants (both languages): `REF_EPOCHS=20`, `ONSET_EPOCHS=30`, `WAKE_EPOCHS=4`, `ONSET_RESET_SEC=1800`, `BASE_EPOCHS=120`, `BASE_MIN_EPOCHS=10`, `STILL_RUN_EPOCHS=10`, `EPISODE_START=6`, `EPISODE_END=2`, `COOLDOWN_SEC=600`, `WAKE_COOLDOWN_SEC=1200`, `RAMP_SEC=120`, `MAX_PER_EPISODE=3`, `WAKE_HR_JUMP=0.15`.
- Cue pattern: 3 pulses, 150 ms on / 150 ms off, at the given duty level. With `vibeByLength=true`: duty 100, and the pulse length is 150 ms for level < 45, 250 ms for level < 60, otherwise 400 ms.
- Log file `GARMIN/APPS/LOGS/LUCIDCUE.TXT` (the PRG must be named `LucidCue.prg`). Line formats, with empty field = null and floats at 1 decimal:
  - `E,<t>,<state>,<motion>,<hrMean>,<hrVar>,<hrBase>,<varBase>,<remLike 0|1>,<episodeId>,<cueEvent>,<level>` with state ∈ `AWAKE|SETTLING|ASLEEP` and cueEvent ∈ `""|cue|wouldcue`.
  - `X,<t>,<name>,<detail>` with name ∈ `night_start|caps|onset|wake_after_cue|absorbed|battery|morning|night_end`.
- Environment: the authoring container cannot reach developer.garmin.com. Python tasks are verified here. Monkey C build/test commands are run by the user on their own machine (Task 12 collects results). Implementers of Monkey C tasks write the test, the code and the commands, mark the "run" steps as **USER-RUN**, and continue.

**Deviations from spec (agreed during planning, spec updated to match):** the Python reference model lives in `model/`; ending the night is START → status → START → confirm (instead of a long-press of Back, which the Epix uses for system functions); the `vibeByLength` setting is added; a "Buzz test" menu item is added to check the vibration-strength unknown.

## Review Focus

1. **HR dropout** (loose strap, sensor gap: `hrMean` null for some epochs) must not crash or create false REM. A null-HR epoch breaks the onset run, is never REM-like, and is excluded from baselines. Tests in Tasks 2, 3 and 8.
2. **Accidental button press while asleep** must not exit the app or end the night. Back is consumed in Night mode, and ending needs a confirmation. Test in Task 11.
3. **Getting up mid-night** (bathroom trip) must not restart the 4.5 h clock unless awake > 30 min. Tests in Tasks 2 and 5.
4. **Out-of-range values from the phone settings app** are clamped, never trusted. Tests in Tasks 1 and 7.
5. **Ending a night before sleep was detected** (or with zero cues) shows "No sleep detected" / "No cues" rather than crashing on a null onset. Test in Task 10.

### Task 2: Python sleep state machine

**Files:**
- Create: `model/lucidcue_model/sleep_state.py`
- Test: `model/tests/test_sleep_state.py`

**Interfaces:**
- Consumes: `Config`, `Epoch` (Task 1).
- Produces: `AWAKE, SETTLING, ASLEEP = "AWAKE", "SETTLING", "ASLEEP"`; `@dataclass(frozen=True) class SleepStatus: state: str; onset_t: int | None`; `class SleepStateMachine(cfg: Config)` with `step(e: Epoch) -> SleepStatus`.

Rules (spec §4.3 made exact):
- Pre-sleep reference `ref` = mean of non-null `hr_mean` over the first `REF_EPOCHS` epochs of the night (any motion).
- "Still" = `motion < still_threshold`. "Wake" epoch = `motion > wake_motion_threshold`.
- `AWAKE` → `SETTLING` on any still epoch.
- In `SETTLING`, an onset run counts consecutive epochs, from epoch index ≥ `REF_EPOCHS` onward, that are still **and** have non-null `hr_mean < ref`. Any other epoch resets the run (and stays `SETTLING`). A run of `ONSET_EPOCHS` → `ASLEEP`. The run start time is the candidate onset.
- From any state, `WAKE_EPOCHS` consecutive wake epochs → `AWAKE`. `awake_since` = t of the first of them.
- On reaching `ASLEEP`: if there was no previous onset, or `run_start_t − awake_since > ONSET_RESET_SEC`, then `onset_t = run_start_t`; otherwise keep the previous `onset_t`.
- In `ASLEEP`, non-wake movement stays `ASLEEP`.

### Task 3: Python REM detector

**Files:**
- Create: `model/lucidcue_model/rem.py`
- Test: `model/tests/test_rem.py`

**Interfaces:**
- Consumes: `Config`, `Epoch`, `SleepStatus`, `ASLEEP`.
- Produces: `@dataclass(frozen=True) class RemStatus: rem_like: bool; episode_active: bool; episode_id: int; hr_base: float | None; var_base: float | None`; `class RemDetector(cfg: Config)` with `step(e: Epoch, s: SleepStatus) -> RemStatus`.

Rules (spec §4.4 made exact):
- The baseline window holds the last `BASE_EPOCHS` epochs that were `ASLEEP`, still, and had non-null `hr_mean`. `hr_base` = mean of their `hr_mean`. `var_base` = mean of their non-null `hr_var`. Both are computed **before** the current epoch is added. Fewer than `BASE_MIN_EPOCHS` entries → bases are `None`.
- The still run = consecutive still epochs including the current one (any state).
- `rem_like` requires: `s.state == ASLEEP`, still run ≥ `STILL_RUN_EPOCHS`, non-null `hr_mean`, non-null `hr_base`, and (`hr_mean >= hr_base*(1+hr_rise)` or (`hr_var` and `var_base` non-null and `hr_var >= var_base*var_ratio`)).
- Episode: becomes active on the `EPISODE_START`-th consecutive `rem_like` epoch (`episode_id` increments, starting at 1). It ends after `EPISODE_END` consecutive non-`rem_like` epochs, or immediately when `s.state != ASLEEP`. `episode_id` keeps its last value while inactive (0 before the first episode).

### Task 4: Python cue controller

**Files:**
- Create: `model/lucidcue_model/cue.py`
- Test: `model/tests/test_cue.py`

**Interfaces:**
- Consumes: `Config`, `Epoch`, `SleepStatus`, `RemStatus`, `ASLEEP`.
- Produces: `@dataclass(frozen=True) class CueDecision: fire: bool; level: int; event: str | None` (event ∈ `None|"wake_after_cue"|"absorbed"`, describing the reaction to the previous epoch's cue); `class CueController(cfg: Config)` with `step(e: Epoch, s: SleepStatus, r: RemStatus) -> CueDecision`, plus properties `cues_tonight: int`, `wakes_after_cue: int`, `cue_log: list[tuple[int, int]]` (t, level). The controller never checks `calibration_mode`: the caller decides whether to vibrate or log `wouldcue`.

Rules (spec §4.5 made exact), evaluated in this order each epoch:
1. **Reaction check.** If a cue fired on the previous epoch: wake if `e.motion > wake_motion_threshold` or (`e.hr_mean` and `r.hr_base` non-null and `e.hr_mean >= r.hr_base*(1+WAKE_HR_JUMP)`). On wake: `event="wake_after_cue"`, `base_level = max(level_min, base_level − level_step)`, cooldown becomes `WAKE_COOLDOWN_SEC`, the current episode id is marked finished, `wakes_after_cue += 1`. Otherwise `event="absorbed"`.
2. **Gates.** All must hold: `s.state == ASLEEP`, `r.episode_active`, `s.onset_t` non-null, `e.t − s.onset_t >= earliest_cue_hours*3600`, `cues_tonight < max_cues_per_night`, and the episode id is not finished.
3. **First cue in an episode** (none yet for this `episode_id`): needs `e.t − last_cue_t >= cooldown` (no previous cue counts as satisfied). It fires at `base_level`. The cooldown resets to `COOLDOWN_SEC` after any non-wake cue.
4. **Ramp cue** (1–2 cues already in this episode): needs `e.t − last_cue_t >= RAMP_SEC` and the previous cue was absorbed. It fires at `min(level_max, base_level + level_step*n)`, where n = cues already in the episode. Cooldown is not checked.
5. After `MAX_PER_EPISODE` cues the episode is finished.
